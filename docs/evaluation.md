# 1차 평가와 도란의 구현

2026-11-14에 확인한 공식 안내의 1차 필수 항목은 **차량특화성·창의성·기술 활용성·사업성**이다. 세부 배점은 공개되지 않았다. 영상·GitHub·APK는 선택 제출 개발 산출물이며 단계별 가산점 대상이다. 아래 내용은 평가항목과 구현을 연결하는 설명으로, 점수나 선정 가능성을 예측하지 않는다. [공식 심사·시상 안내](https://appdevchallenge.auto-hmg.io/guide/judging-awards)

## 항목별 설명과 증거

| 평가항목 | 도란이 제안하는 가치와 구현 | 현재 제시할 수 있는 증거 | 제출 전 남은 확인 |
|---|---|---|---|
| **차량특화성** — 모바일 대비 가치, 주행·정차와 차량 기능의 결합 | 이동 중 떠오른 이야기를 음성으로 남기고, 긴 글의 확인·수정은 모바일에서 이어간다. 유효한 목적지 남은 시간과 도착 이벤트를 대화 마무리에 활용하고, 동승 여부가 불명확하면 사적인 과거 이야기를 먼저 꺼내지 않는다. 주행 중에는 원문·코드·설정을 숨기고 최소 제어만 제공한다. | [차량 구현](car.md), [신호의 출처·유효성·권한 처리](car-sdk.md), [개인화 전송 조건](backend.md). SDK 연결 코드와 정책 시험을 근거로 설명한다. | 실제 SDK 신호와 화면의 일치, 주차→주행→주차, 분할 화면, 내비·통화 개입, 실제 사람의 음성 대화. 기획상 편의나 센서 지원을 실차 검증 결과로 표현하지 않는다. |
| **창의성** — 운전자·동승자의 필요와 해결 방식 | 기록을 따로 쓰기 어려운 순간의 대화를 개별 기록과 하루 일기로 이어간다는 가설이다. 기억의 근거를 사용자 발화에 연결하고, 정정·개인화 제외·삭제를 반영한다. 사용자가 직접 고친 일기는 유지하며 새로운 AI 초안을 비교해 선택한다. 이는 도란의 설계 선택이며 시장 최초라고 주장하지 않는다. | [기록·기억 생성과 수정 보호](backend.md), [모바일 편집과 충돌 처리](mobile.md). 실제 클라우드 HTTP 시험에서 AI 대화, 큐 처리, 일기 생성과 수동 수정 보호를 확인했다. [검증 기록](verification.md) | 설치 앱에서 과거 이야기→정정→종료→모바일 확인·수정→새 초안 비교를 연속 시연한다. 실제 사용자의 기록 부담 감소와 선호는 아직 조사하지 않았다. |
| **기술 활용성** — Pleos SDK/API의 핵심 경험 기여 | SpeechToText·TextToSpeech가 음성 입출력을 맡고, NaviHelper·Vehicle·FusedLocation이 허용된 차량 맥락을 제공한다. 정밀 좌표는 기기에 두며, 출처와 측정 시각을 검증한 맥락만 서버에 보낸다. DO 선언·CarUxRestrictions·오디오 포커스와 요청별 취소 처리를 함께 적용한다. | [사용 SDK·버전·데이터 범위](car-sdk.md), [API 계약](../contracts/api.md), [사용자별 인증·RLS·큐·예산 경계](backend.md). 빌드·단위 시험, 실제 클라우드 시험, 합성 한국어 텍스트의 실제 모델 평가를 구분해 기록했다. | SDK 콜백 수신과 실제 청취를 별도로 확인한다. 20회 연속 사람 발화, 첫 음절 손실, 오프라인 복구와 늦은 응답 차단을 검증한다. 서버 HTTP 성공은 Google 로그인·마이크·TTS·모바일 화면 성공을 뜻하지 않는다. |
| **사업성** — 타깃, 사용자 확보와 반복 이용·확대 | 초기 타깃은 혼자 반복 이동하며 하루의 경험을 남기고 싶은 운전자라는 **가설**이다. 첫 대화 이후 모바일에서 읽고 다듬은 기록이 다음 대화와 연결되는 반복 흐름을 설계했다. 초기에는 소규모 사용성 시험으로 필요와 부담을 확인하고, 검증 후 Pleos 사용자를 대상으로 확대 여부를 판단한다. | 현재 근거는 동작하는 기능과 제한된 기능 시험이다. 실제 이용자 수·MAU·재사용률·매출·지불 의향을 측정한 자료는 없다. | 타깃 인터뷰와 일정 기간의 자발적 사용 관찰이 필요하다. 예상 수치를 제시하려면 모집 규모·관찰 기간·활성 기준·전환 가정을 함께 적고 실측과 분리한다. App Market 입점·매출을 확정 성과로 표현하지 않는다. |

## 사업성에서 앞으로 측정할 항목

아래는 **향후 검증 계획**이다. 지금 앱에 운영 분석 수집이 구현되어 있거나 수치 목표가 달성됐다는 뜻이 아니다. 연구 참여와 데이터 수집 범위를 먼저 안내하고 필요한 항목만 측정한다.

| 확인할 질문 | 측정 기준 | 해석의 한계 |
|---|---|---|
| 첫 경험을 끝낼 수 있는가 | 모집 참여자 중 계정·차량 연결과 첫 대화 저장을 완료한 비율, 중단 사유 | 내부 시험 계정의 성공 횟수를 고객 활성화율로 계산하지 않는다. |
| 다시 사용할 이유가 있는가 | 첫 사용 7일째 대화 완료 또는 기록 조회를 한 참여자의 비율. 분모는 7일 관찰이 끝난 최초 사용자 | 작은 자발적 표본의 결과를 전체 운전자 유지율로 일반화하지 않는다. |
| 기록이 유용한가 | 기록을 읽거나 직접 수정한 이유, 잘못된 기억·정정 경험, 사용 중 부담에 대한 인터뷰 | 수정 횟수가 많다는 사실만으로 만족도가 높다고 판단하지 않는다. |
| 운영 가능한 비용인가 | 대화·기록 생성별 실제 토큰 사용량과 청구 비용, 처리 실패율·응답 지연 | 현재 앱의 보수적 예산 차감액은 청구서 금액이 아니다. 30달러 시험 한도는 사업 수익성 근거가 아니다. |

예상 MAU나 매출을 추후 작성할 때에는 사용자 확보 경로, 모집·전환 가정, 기간을 명시한다. 현재는 이를 뒷받침할 관측 자료가 없어 숫자를 제시하지 않는다.

## 제출 영상과 연결

[약 3분 시연 구성](submission.md)의 대화 이어가기·정정·자동 기록·수동 일기 보호·삭제 흐름으로 위 주장을 보여 준다. 에뮬레이터 신호와 예시 기록은 표시하고, 실제 앱의 연속 동작 구간을 포함한다. 소스·APK·영상의 기준 버전을 함께 고정한다.

검증이 진행 중이므로 완료 여부와 최신 결과는 [검증 기록](verification.md)을 기준으로 한다. 기능 구현, 자동 시험, 실제 클라우드 호출, SDK 실행, 사람의 사용 경험을 서로 대신하는 증거로 쓰지 않는다.
