# 도란 서버

Supabase 프로젝트는 서울 리전의 `lokvjxxtnnzxnkjiehja`이다. 실제 API 주소는 `https://lokvjxxtnnzxnkjiehja.supabase.co/functions/v1/doran-api/v1`이며 요청 계약은 `contracts/api.md`에 있다.

## 인증과 데이터 경계

모바일은 Google OAuth/PKCE로 로그인한다. 차량은 별도 Supabase 익명 사용자이며, 5분짜리 일회용 코드로 모바일의 주장과 차량의 최종 확인을 모두 거쳐 연결한다. 차량에 모바일의 계정 토큰을 복사하지 않는다. DB의 사용자 식별자는 요청 본문에서 받지 않고 인증 서버가 확인한 JWT 사용자에서 가져온다.

운영 프로젝트에서 이메일·비밀번호 로그인은 비활성화했다. 실제 HTTP 통합 시험에 사용한 임시 비밀번호 계정과 익명 차량 계정은 시험 뒤 삭제했다. 이 시험의 재실행은 별도 시험 프로젝트에서 준비한 계정으로 수행하며, 운영 Google 로그인 검증과 구분한다.

Edge Functions는 플랫폼 JWT 자동검사를 끄고 함수 내부에서 Supabase Auth `/user`로 토큰을 확인한다. 이는 새 publishable key와 익명 차량 인증을 일관되게 처리하기 위한 것으로, 인증 생략이 아니다. 고정 텍스트 `/about`, `/privacy`만 공개다. 함수의 서비스 키는 Supabase 런타임 환경 변수만 사용한다.

공개 스키마 테이블의 RLS는 모바일 사용자의 소유 데이터 SELECT만 허용한다. 쓰기와 작업 함수는 service_role만 실행할 수 있다. 차량은 직접 전체 기록을 읽지 못한다. 계정 삭제의 앱 데이터 제거와 Auth 삭제 사이 실패는 삭제 표식과 재시도로 처리한다.

## 대화와 개인정보

모든 음성 인식은 차량의 Pleos SDK에서 수행된다. 서버 입력은 텍스트와 허용된 차량 맥락이며 원시 음성·GPS 좌표·연속 경로는 받지 않는다. 요청 종료·시간 초과·네트워크 중단 뒤에도 완료된 사용자 발화는 차량의 암호화된 outbox에서 보관하고 finish 요청으로 중복 없이 저장할 수 있다.

취소되거나 실패한 발화는 같은 요청 ID와 같은 원문으로 재시도한다. 원문 메시지는 한 번만 저장하고, 서버 내부의 시도 세대를 증가시켜 이전 응답의 성공·실패 콜백을 차단한다. 완료되지 않은 요청이 90초 이상 남으면 같은 ID로 회수할 수 있으며 종료한 세션은 다시 열지 않는다. 세대는 서버 내부 계약이므로 모바일·차량 요청 형식은 바뀌지 않는다.

과거 자료는 현재 사용자 범위에서 검색한다. 동승 감지 또는 불명확한 좌석 상태에서는 명시적인 과거 기록 조회 요청이 없는 한 개인 기억을 외부 모델에 보내지 않는다. 부정문·인용·가정은 조회 허가로 처리하지 않는다. 대화의 텍스트와 음성용 문장은 데이터 변경 버전 확인을 거친 뒤 전달한다.

AI는 Responses API의 `gpt-6.1-terra`를 사용하며 `store:false`, 제한된 출력 토큰, 낮은 reasoning effort를 설정한다. API 키가 없으면 503을 반환하고 규칙 기반 또는 가짜 AI 응답을 대신 생성하지 않는다.

## 기록과 백그라운드 작업

개별 기록의 원문, AI 생성본, 사용자 수정본을 분리한다. 하루 일기는 최신 개별 기록으로 갱신하고 사용자 수정본을 덮어쓰지 않는다. 개별 기록 삭제 시 관련 원문·기억·색인 및 오래된 AI 일기를 제거하며, 직접 수정한 하루 일기는 명시적으로 함께 삭제를 선택했을 때만 지운다.

작업은 실제 Supabase Queues(pgmq)에 ID를 넣고 private 작업 메타데이터에 원본 버전·임대 토큰·재시도 횟수를 저장한다. 완료 시 원본과 동의 버전을 다시 비교한다. 취소·삭제·제외·정정 이후 오래된 작업 결과는 게시하지 않는다. 실패는 최대3회 재시도하며 사용자가 재시도할 수 있다.

개인화 기억은 사용자 원문의 정확한 근거 구절이 있어야 저장된다. 정정은 같은 소유자의 현재 버전 기억 후보 ID를 지정하고, 새 원문에 명시적 정정 근거가 있는 경우에만 이전 기억을 비활성화한다. 수정된 기록에는 이전의 수정 전 원문을 다시 AI 근거로 전달하지 않는다.

## 예산과 운영

개발 시험과 심사 운영을 합친 총 AI 예산 한도는 30USD이다. 초기 배포의 DB 운영 한도는 29USD로 설정했고, 별도 OpenAI 연결 확인과 한국어 텍스트 평가를 위해 1USD를 유보했다. 직접 API 시험도 이 유보금 안에서 호출 전에 비용 상한을 확인한다. 요청 입력의 UTF-8 바이트 수, 고정 프롬프트·스키마 여유분, 최대 출력 토큰으로 비용을 먼저 원자적으로 예약한다. 응답 뒤 확정하는 **앱 예산 차감액**은 입력2USD/백만 토큰·출력5USD/백만 토큰의 보수적인 상한이다. 이는 실제 청구서 금액이 아니다. 공식 기본 입력 가격1USD 외 캐시 쓰기 비용 등을 보수적으로 포함한다. 사용량을 알 수 없는 중단은 예약금을 유지한다.

사용자별 요청 제한과 전역 예산 한도는 DB에서 적용한다. 예산이 부족하면 AI 호출은 거절하지만 기록 열람은 유지한다. 비공개 예산 테이블, 큐, 워커 인증 토큰에는 앱 사용자가 접근할 수 없다.

현재 프로젝트의 29USD 운영 한도는 관리자 배포 설정이다. 새 프로젝트에서 외부 평가비 1USD를 함께 유보하려면 아래 설정을 적용한다. 마이그레이션의 기본 30USD를 그대로 둔 채 외부 평가비를 추가로 쓰지 않는다.

```sql
update private.budget set limit_usd = 29 where id = 1;
```

## 검증

```sh
deno task --config supabase/deno.json check
deno task --config supabase/deno.json test
deno lint --config supabase/deno.json supabase/functions supabase/tests
```

`supabase/tests/sql`은 별도 Supabase PostgreSQL에서 migration 적용 후 실행하는 트랜잭션 rollback 시험이다. 로컬 Auth 호환성 shim은 호스팅된 DB에 적용하지 않는다. SQL 테스트와 모의 provider의 HTTP 시험은 실제 OpenAI 품질 검증이 아니다. 한국어 기본 30개 및 시각 회귀 2개 시나리오와 실제 API 실행기는 `supabase/tests/evals`에 별도로 있다. 실제 모델 평가, 클라우드 HTTP·큐 시험, SDK와 사람 발화 시험은 [검증 기록](verification.md)에서 구분한다.

## 시도 세대 마이그레이션 배포 순서

`doran_turn_generations`는 Edge Function과 DB 내부 계약을 함께 변경한다. 먼저 API가 모든 `turns.validate/complete/fail`에 캡처한 세대를 전달하도록 배포한다. 이전 DB가 세대를 반환하지 않으면 API는 최초 세대 1을 사용하며 이전 DB는 추가 필드를 무시하므로 이 순서는 호환된다. 진행 중 발화가 없는지 확인한 뒤 DB 마이그레이션을 적용한다.

새 DB는 세대가 없는 콜백을 거부한다. 따라서 DB 적용 뒤 API만 이전 버전으로 되돌리면 대화 응답 처리가 실패한다. 문제가 생기면 세대를 전달하는 API를 유지하고 수정 버전을 배포한다. DB 정의를 되돌려야 할 때는 진행 중 요청을 중단한 별도 배포 창에서 함께 검토해야 하며, 이전 정의에는 취소 재시도 및 늦은 콜백 결함이 다시 생긴다. 배포 전 DB 함수 정의는 공개 저장소 밖에 권한을 제한해 보존한다. 개인 데이터나 예산 원장을 되돌리는 방식으로 복구하지 않는다.
