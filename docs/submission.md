# 도란 1차 제출 준비

이 문서는 제출 산출물과 최종 확인 절차를 설명한다. 실제 검증 상태는 [검증 기록](verification.md)을 따른다.

## 제출 산출물

| 산출물 | 포함할 내용 |
|---|---|
| GitHub | 제출 기준 커밋, 전체 소스, 실행 방법, 테스트 환경, 필요한 설정 |
| 차량 APK | 서명된 실행 가능한 release 빌드, 저장소 `apk/` 폴더 |
| 모바일 APK | 같은 서버 계약을 사용하는 Android release 빌드 |
| 화면 녹화 | 실제 설치 앱의 음성 대화·기록 저장·수정 보호·삭제 반영 |
| 검증 자료 | 확인된 동작, 미확인 조건, 앱·서버 버전, 파일 SHA-256 |

공식 제출 안내는 release APK와 소스, 최종 커밋 번호, Pleos Connect 에뮬레이터 버전·화면 규격을 요구한다. APK·영상이 저장소 업로드 한도를 넘으면 GitHub Releases 경로를 사용한다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)

팀명 확정 전 빌드 보관 이름은 `doran-car-release.apk`, `doran-mobile-release.apk`를 사용한다. 실제 제출 시 차량 APK를 공식 형식인 `팀명_도란_release.apk`로 정리한다. 파일명만 변경해도 SHA-256은 동일하지만 최종 목록의 경로는 다시 확인한다.

현재 차량·모바일의 수정된 release APK 빌드와 독립 공개 검사를 마쳤다. 모델 직접 평가와 별도 debug 앱의 최초 합성 PCM 1회와 후속 3회 SDK 관측도 기록했다. 이 계측은 제출 release의 사람 음성 시연을 대신하지 않는다. Android·iOS의 로그인 전 실제 화면과 B4 차량의 코드 재시작 복원은 확인했다. Google 인증 완료부터 기록 삭제까지의 앱 통합 검증, 사람 발화, 제출 영상은 별도로 완료해야 한다. 최신 해시와 관측 범위는 [검증 기록](verification.md)을 확인한다. APK가 생성됐다는 사실만으로 제출 패키지가 완료된 것은 아니다. 연결 코드 복원이 추가된 최신 차량 APK와 이전 UI·SDK 시험 파일의 버전을 구분하며, 최종 녹화에는 고정한 제출 APK를 사용한다.

## 약 3분 시연 구성

1. **서비스와 상태 소개:** 차량에서 이야기하고 휴대폰에서 기록을 다듬는 용도를 설명한다. Pleos 에뮬레이터·예시 기록임을 표시한다.
2. **대화 이어가기:** 과거 발표 이야기를 참고하는 실제 대화와 사용자의 정정을 보여준다. 음성 상태와 일시정지·종료 조작을 포함한다.
3. **자동 기록과 연동:** 대화를 종료하고 모바일에서 새 개별 기록과 갱신된 하루 일기를 확인한다.
4. **내 글 보존:** 직접 수정한 하루 일기가 새 AI 초안과 분리되어 유지되는 과정을 보여준다.
5. **기록 통제:** 개인화 제외 또는 삭제 후 화면과 이후 대화에 반영되는 동작을 보여준다.

핵심 흐름에는 무편집 구간을 포함한다. 합성 발화, 미리 준비한 과거 기록, 가상 차량 신호를 사용한 경우 표시한다. 편집으로 응답 지연이나 실패를 숨기지 않는다. Google 계정 정보·연락처·키·개발자 도구의 비밀값은 영상에 노출하지 않는다.

## 최종 고정 절차

- 모든 release 시험이 끝난 뒤 제출 기준 커밋을 고정한다.
- 영상에 사용한 APK와 제출 APK가 같은 파일인지 SHA-256으로 확인한다.
- README에 APK 경로, 실제 지원 범위, 온라인 서비스에 필요한 설정을 연결한다.
- 공유 링크를 새 세션에서 열어 접근 가능 여부와 파일 다운로드를 확인한다.
- 공개 검사기 실행 후 스크린샷·영상·라이선스를 수동 확인한다.
- 완료하지 못한 기능이나 미검증 환경은 그대로 명시한다. 기획상의 기능을 실제 구현 결과로 표현하지 않는다.

검증한 소스·문서를 먼저 커밋하고, 저장소 루트에서 다음 명령으로 산출물을 묶는다. 경로와 팀명은 실제 값으로 바꾼다. 빌드나 화면 녹화를 대신 생성하는 명령이 아니다.

```sh
python3 scripts/package-release.py \
  --car-apk /absolute/path/to/car-release.apk \
  --mobile-apk /absolute/path/to/mobile-release.apk \
  --video /absolute/path/to/doran-demo.mp4 \
  --team 확정팀명 \
  --version 1.0.0
```

도구는 소스 작업 폴더의 변경 여부, 기존 출력 충돌, APK 공개 검사, 영상 길이를 확인한 뒤 `apk/`, `demo/`, `release-manifest.json`을 생성한다. manifest에는 `release_version`과 파일 해시가 들어간다. `source_commit`은 포장 시 소스 커밋이므로, 해당 커밋으로 빌드·시연했다는 별도 검증을 완료해야 한다. 새 산출물과 manifest를 추가 커밋하여 최종 제출 커밋을 기록한다. 영상 내용·개인정보·실제 앱 흐름의 수동 검토와 APK 서명 검사는 이 명령이 대신하지 않는다.

팀명이 미정이면 `--team 확정팀명` 대신 `--provisional-team`을 사용한다. 이 경우 APK 이름은 `doran-car-release.apk`, `doran-mobile-release.apk`이며 manifest의 `team_name`은 null, `naming_status`는 `provisional`로 남긴다. 실제 접수 전 팀명이 정해지면 공식 파일명으로 변경하고 manifest의 경로·팀명을 갱신한다. 파일 내용이 같으면 SHA-256은 유지된다.

공모전 이메일 접수는 앱 제작과 별도 작업이다. 제출용 신청서·서명·개인 연락처와 팀 내부 대화는 공개 저장소에 넣지 않는다.
