# 검증 범위

검증은 자동 시험, 실제 SDK·서버 연결, 앱 화면 관측으로 구분합니다. 아래는 2026년 11월 15일까지 확인한 범위입니다.

## 제출 APK의 촬영 중 확인

차량 `dc6b20f`, 모바일 `60141ae`의 release APK를 사용했습니다. 입력은 합성 음성 파일이며 물리 마이크를 수음하지 않았습니다.

| 항목 | 확인한 결과 |
|---|---|
| 음성 대화와 저장 | 회의 후의 후련함, 산책하며 느낀 차분함, 다음 회의의 메모 계획을 세 번의 대화로 진행. 실제 Pleos STT 인식, 서버 AI 응답, 개별 기록 3개 생성을 확인 |
| 정정 | 회의 대화에서 잘못 인식된 내용을 추가 발화로 정정하고 수정된 사실이 기록 요약에 반영됨을 확인 |
| 중단과 재개 | 기록 날짜 변경이 진행 중 대화와 겹치면 이전 버전의 응답을 중단. 정상 재개와 최초 사용자 발화 보존을 확인 |
| 수동 일기 보호 | Android에서 한국어로 직접 수정본을 입력·저장. 새 대화가 추가된 뒤에도 같은 본문이 유지됨을 앱과 서버에서 확인 |
| AI 초안 비교 | 개별 기록 3개와 새 AI 초안의 회의·산책·다음 회의 계획 통합을 모바일에서 확인. 비교 화면을 열어도 직접 수정본을 덮어쓰지 않음 |

시연용 새 기록 3개만 정상 API로 같은 날짜에 배치했으며 기존 기록은 보존했습니다. 이번 촬영에서는 영구 삭제를 실행하지 않았습니다. 대화를 종료한 뒤 과거 발표 시간을 다시 조회하는 흐름은 성공을 확인하지 못했습니다. 합성 입력 결과를 사람 발화 20턴이나 음질 검증으로 계산하지 않습니다.

## 빌드와 자동 시험

| 대상 | 확인한 결과 |
|---|---|
| 차량 | JVM 63개 시험, Kotlin 포맷 검사, Android 정적 검사, release 서명 검사 |
| 모바일 | 단위·위젯 시험 72개, Dart 분석, Android release 및 iOS 시뮬레이터 빌드 |
| 서버 | Deno 30개 시험, SQL 105개 검증, 동시성 시험 4개 |
| 한국어 대화 | 합성 텍스트 30개를 실제 모델로 평가. 사례별 기준에서 30개 통과. 사실 추가를 더 엄격히 검토한 결과는 29개 통과, 1개 불명확 |

차량 제출 후보의 빌드 소스는 `dc6b20f`, 모바일은 `60141ae`입니다. [CI 결과](https://github.com/Mango-Juice/doran/actions/workflows/verify.yml)에서 서버·SQL·차량·모바일 작업을 확인할 수 있습니다. 자동 시험은 사람 발화 인식률이나 실차 성능을 의미하지 않습니다.

## 앱과 서버에서 확인한 동작

| 영역 | 확인한 범위 |
|---|---|
| 계정·연결 | Android·iOS Google 로그인, 모바일과 차량의 양쪽 승인, 같은 계정의 재로그인·연결 해제·재연결 |
| 음성·기록 | 사람 발화의 서버 응답과 대화 종료 후 개별 기록·하루 일기 생성. 별도 SDK 시험의 TTS 취소·재개와 오디오 포커스 상실 처리 |
| 기록 편집 | Android 기록·날짜 수정, 수동 일기 보존, AI 초안 비교·반영, 개인화 제외, iOS 교차 조회·수정 |
| 충돌·삭제 | Android 편집 중 서버 버전 변경에 따른 409 처리, 작성 내용 보존과 명시적 덮어쓰기, 개별 기록 삭제 후 서버 수동 일기 보존 |
| 최신 모바일 수정 | 마지막 개별 기록 삭제 뒤 남은 수동 일기의 Android·iOS 표시·편집, 빈 AI 초안 비교 미노출 |
| 차량 제한 | 에뮬레이터의 주행·정차 전환과 분할 화면. 합성 대화 상태의 제한 대응 |
| 장애 복구 | 로컬 시험 서버의 TCP 단절·프로세스 재시작 후 같은 요청 복구. 서버의 중복 요청 및 오래된 결과 차단 |

로그인·편집·삭제 일부는 이전 APK에서 확인한 결과입니다. 최신 모바일 빌드에서는 같은 잔존 수동 일기의 표시와 편집을 확인했으며, 삭제 전체 동작을 다시 실행한 결과로 계산하지 않습니다. 실제 내비 안내·전화 앱의 개입과 합성 포커스 시험도 구분합니다.

## 음성 환경과 한계

Mac의 Pleos 에뮬레이터 직접 출력에서 잡음이 관측됐습니다. 공식 gRPC 출력으로 수집한 SDK 원음은 별도 파일 청취에서 깨끗하게 들렸습니다. 이 결과는 호스트 출력 경로의 관측이며 APK의 음질 개선이나 실차 음질을 입증하지 않습니다. 재현 방법은 [에뮬레이터 오디오 안내](emulator-audio.md)에 있습니다.

실차·실도로, 20턴 연속 사람 발화, 장시간 음성 안정성, 실제 클라우드 음성 중 네트워크 복구는 추가 검증 대상입니다. iOS AI 초안 전체 반영, 두 클라이언트의 동시 편집, 다른 계정 전환·계정 삭제도 별도 통합 검증이 필요합니다.
