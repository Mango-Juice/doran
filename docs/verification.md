# 검증 범위

검증은 자동 시험, 실제 SDK·서버 연결, 앱 화면 관측으로 구분합니다. 아래는 2026년 11월 15일까지 확인한 범위입니다.

## 제출 APK의 촬영 중 확인

촬영한 release APK의 SHA-256은 차량 `57d74e10…`, 모바일 `62333cc5…`입니다. 합성 사용자 음성을 가상 마이크로 입력하고 같은 촬영의 실제 Pleos TTS 출력을 수집했으며, 목적지, 차량 상태와 이전 회사 기록은 시연용으로 준비했습니다.

| 항목 | 확인한 결과 |
|---|---|
| 차량 맥락 대화 | 실제 NaviHelper의 가상 목적지와 남은 시간이 서버에 전달되고, 회사 기억과 앞서 말한 식사 약속을 참고한 첫 응답을 확인 |
| 음성 대화와 저장 | 출근길과 저녁 약속의 대화, 귀가길에 회의 걱정을 들어주는 대화에서 실제 Pleos STT 인식과 AI 응답, 개별 기록 3개 생성을 확인 |
| 수동 일기 보호 | Android에서 한국어 직접 수정본을 입력하고 저장. 귀가길 대화가 추가된 뒤에도 같은 본문이 유지됨을 앱과 서버에서 확인 |
| 하루 일기 통합 | 세 개별 기록의 기대감, 약속 장소로 향하는 기분, 식사 후 풀린 긴장이 새 AI 초안에 함께 반영됨을 앱과 서버에서 확인. 비교 후 돌아와도 직접 수정본 유지 |

시연용 새 기록만 정상 API로 같은 날짜에 배치했으며 기존 기록은 보존했습니다. 영구 삭제는 실행하지 않았습니다. 합성 입력 결과를 사람 발화 20턴이나 실차 음질 검증으로 계산하지 않습니다.

## 빌드와 자동 시험

| 대상 | 확인한 결과 |
|---|---|
| 차량 | JVM 64개 시험, Kotlin 포맷 검사, release 정적 검사, 서명 확인 |
| 모바일 | 변경된 도메인 시험 9개, Dart 분석, Android release 서명, iOS 시뮬레이터 빌드 |
| 서버 | Deno 31개 시험, 새 SQL 13개와 기존 SQL 46개 검증. 로컬 권한 호환 계층을 사용했으며 실제 pgmq 실행은 제외 |
| 이전 한국어 대화 평가 | 합성 텍스트 30개를 실제 모델로 평가. 사례별 기준에서 30개 통과. 사실 추가를 더 엄격히 검토한 결과는 29개 통과, 1개 불명확 |

변경 전 전체 시험에서는 모바일 72개, SQL 105개와 동시성 4개가 통과했습니다. 표의 차량, 모바일, 서버 행은 후속 변경에서 수행한 검사이며, 실제 배포 큐의 대화 응답과 기록 생성은 별도로 확인했습니다. 빌드 입력은 [파일 목록](../release-manifest.json), 자동화 작업은 [CI](https://github.com/Mango-Juice/doran/actions/workflows/verify.yml)에서 확인합니다.

## 앱과 서버에서 확인한 동작

| 영역 | 확인한 범위 |
|---|---|
| 계정·연결 | Android·iOS Google 로그인, 모바일과 차량의 양쪽 승인, 같은 계정의 재로그인·연결 해제·재연결 |
| 음성·기록 | 사람 발화의 서버 응답과 대화 종료 후 개별 기록·하루 일기 생성. 별도 SDK 시험의 TTS 취소·재개와 오디오 포커스 상실 처리 |
| 기록 편집 | Android 기록·날짜 수정, 수동 일기 보존, AI 초안 비교·반영, 개인화 제외, iOS 교차 조회·수정 |
| 충돌·삭제 | Android 편집 중 서버 버전 변경에 따른 409 처리, 작성 내용 보존과 명시적 덮어쓰기, 개별 기록 삭제 후 서버 수동 일기 보존 |
| 수동 일기 표시 | 마지막 개별 기록 삭제 뒤 남은 수동 일기의 Android·iOS 표시·편집, 빈 AI 초안 비교 미노출 |
| 차량 제한 | 에뮬레이터의 주행·정차 전환과 분할 화면. 합성 대화 상태의 제한 대응 |
| 장애 복구 | 로컬 시험 서버의 TCP 단절·프로세스 재시작 후 같은 요청 복구. 서버의 중복 요청 및 오래된 결과 차단 |

이 표의 로그인, 편집, 삭제와 수동 일기 표시 검증에는 이전 APK의 결과가 포함됩니다. 현재 촬영 APK에서 삭제 전체 동작을 다시 실행한 결과로 계산하지 않습니다. 실제 내비 음성과 전화 앱의 개입은 합성 포커스 시험과 구분합니다.

## 음성 환경과 한계

Mac의 Pleos 에뮬레이터 직접 출력에서 잡음이 관측됐습니다. 공식 gRPC 출력으로 수집한 SDK 원음은 별도 파일 청취에서 깨끗하게 들렸습니다. 이 결과는 호스트 출력 경로의 관측이며 APK의 음질 개선이나 실차 음질을 입증하지 않습니다. 재현 방법은 [에뮬레이터 오디오 안내](emulator-audio.md)에 있습니다.

실차·실도로, 20턴 연속 사람 발화, 장시간 음성 안정성, 실제 클라우드 음성 중 네트워크 복구는 추가 검증 대상입니다. iOS AI 초안 전체 반영, 두 클라이언트의 동시 편집, 다른 계정 전환·계정 삭제도 별도 통합 검증이 필요합니다.

## 공개 산출물 검사

소스와 APK는 [공개 검사 도구](../scripts/verify-publication.py)로 비밀값, 개인 경로, 시험 자산과 release 설정을 확인합니다. 이미지·영상의 개인정보, APK 서명·설치·서버 연결은 별도로 검토합니다. 파일 해시는 [제출 파일 목록](../release-manifest.json)을 기준으로 대조합니다.
