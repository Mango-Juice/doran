# 에뮬레이터 음성 시험 재개 안내

2026-11-14 사용자가 준비만 요청한 이후 단계에서는 녹음·촬영을 보류했다. 이 단계는 [도구 소스](../scripts/emulator-audio/README.md) 보존, 의존성 고정, 읽기 검토와 순수 로직 시험에 한정하며 재생·수음·에뮬레이터 기동을 수행하지 않았다. 그 전에 수행한 실제 청취와 진단은 아래에 별도로 기록한다.

## 확인한 범위와 남은 범위

같은 PCM이 호스트에서는 깨끗하고 guest CoreAudio 경로에서는 거칠게 들렸으며, 비교한 두 설정·마이크 비활성·이전 36.6 에뮬레이터에서도 문제가 관측됐다. `QEMU_AUDIO_DRV=none`과 설치된 Emulator의 인증된 gRPC `streamAudio`로 받은 원본은 분석과 사용자의 파일 청취에서 깨끗했다. 이는 관측한 경로의 결과이며 모든 에뮬레이터·장치의 원인을 일반화하지 않는다.

이전 paced 출력 도구의 실제 SDK TTS도 사용자가 끝까지 깨끗하게 들었다고 확인했다. 다만 해당 실행은 약 23초 뒤 100ms 지연 보호 조건으로 중단됐다. 이후 clock rebase·작은 지터 누적 처리와 최대 실행 시간을 보완한 소스는 순수 시험만 통과했다. 최신 소스의 장기 실시간 안정성, 새 실제 마이크 입력부터 SDK 인식까지의 통합, 첫 음절과 사람 발화 20턴은 미검증이다. 짧은 음질 확인을 이 항목들의 성공으로 계산하지 않는다.

## 재개 순서

1. [launch.py 안내](../scripts/emulator-audio/README.md)에 따라 기존 기기·계정 데이터를 보존한다. 장치와 토큰 파일을 확인하되 값을 출력하지 않는다. 현재 호스트의 음량·무음 상태를 임의로 바꾸지 않는다.
2. 출력 캡처와 실제 재생을 구분한다. `stream_output.py`의 기본값은 호스트 재생 꺼짐이며 `--play`를 명시해야 재생한다. 출력 폴더와 PCM·WAV·패킷 시각·재생 tick 보고서는 비공개로 보존한다.
3. 사용자 시작 지시 뒤 선택한 실제 마이크를 `inject_microphone.py --record-microphone`로 연결한다. 입력 원본 PCM/WAV와 도착 시각을 보존한다. 텍스트 주입·합성 발화를 사람 발화로 대신하지 않는다. 기본적으로 수음하지 않으며, 입력 도구는 출력 장치를 변경하거나 소리를 재생하지 않는다.
4. 짧은 파일럿에서 실제 SDK 인식·TTS·사용자 청취를 확인한 뒤 연속 턴을 시도한다. 충분한 시간은 `--seconds 900` 등으로 명시한다. 1,800초 상한이나 400ms 버퍼 설정을 안정성 통과로 해석하지 않는다.
5. 실패·중단·정리 결과와 실제 사용한 소스 SHA를 함께 남긴다. 프롬프트·발화 원문, 연결 코드·계정·토큰·개인 장치명이 포함된 원본은 공개하지 않는다.

입력은 기본 `--input-mode blocking`(proto mode 0)이며 명시적으로 `realtime`(mode 1)을 선택할 수 있다. realtime의 늦은 입력 덮어쓰기 가능성과 실제 SDK 통합 미검증을 전제로, 재개 시 짧은 파일럿에서 먼저 확인한다. 앱 자체의 음성 원본 미저장 정책과 달리 이 외부 시험 도구는 승인된 시험의 진단 원본을 비공개로 보존한다.

출력 도구의 400ms 한도는 애플리케이션 FIFO와 쓰기 완료를 기다리는 source byte의 한도다. OS pipe·ffplay·SDL 버퍼나 실제 스피커까지의 지연 한도가 아니며 전체 지연은 측정하지 않았다. 명시적인 재생 gain은 호스트 청취 경로에만 적용하고 보관 원본 PCM에는 적용하지 않는다.

## 영상과 원본 보존

영상·guest 출력·사람 마이크는 같은 촬영 회차의 원본을 보존한다. 매 회차 준비 구간으로 오프셋을 새로 측정하며 이전 회차 값을 재사용하지 않는다. gRPC 원본 WAV는 수신 패킷 순서를 보존하지만 idle gap을 합성해서 넣지는 않는다. 따라서 해당 WAV를 곧바로 영상의 벽시계 시각과 일치한다고 가정하면 안 된다. 패킷 시각과 그 회차 준비 구간을 근거로 정렬해야 한다.

[edit-demo.py](../scripts/edit-demo.py)는 이미 존재하는 녹화 파일을 편집하는 도구다. 녹화·VM 기동·대화 생성·자동 재생을 하지 않으며 `--validate-only`도 ffprobe를 이용하는 읽기 검사다. gRPC 패킷 시각을 영상 타임라인으로 자동 복원하거나 입력 장치의 정확한 capture PTS를 보장하지 않는다. 실제 device audio가 들어 있는 입력 영상과 별도 사람 음원의 정렬 근거를 준비한 뒤 사용한다.

편집본에는 가상 사례·합성 입력 여부, 중복 수음 제거와 잘라낸 구간을 명시한다. 원본은 덮어쓰지 않고 연속 무편집 구간을 보존한다. 현재는 새 녹화·완성 영상·최종 제출 패키지를 만들지 않았다.
