# 모바일 변경·충돌·삭제의 서버 대조

2026-11-14의 두 번째 모바일 합성 회귀를 서버에서 대조한 기록이다. 초기 자료는 빈 시험 날짜인 11월 1일에 관리자가 준비했으며, 사람의 대화나 AI 생성 증거로 계산하지 않는다. 원래 Google 계정의 실제 기록 3개와 하루 일기 1개는 수정하지 않았다. 계정 토큰·식별자·실제 본문·본문 해시는 공개하지 않는다.

## 실제 UI와 서버 대조

| 항목 | 관측 결과 |
| --- | --- |
| iOS → Android 변경 조회 | iOS에서 저장한 기록·수동 일기의 같은 문자열을 Android와 서버에서 확인했다. |
| 개별 기록 충돌 | 정상 version/CAS RPC로 만든 경합에서 실제 PATCH 409를 확인했다. ‘계속 수정’은 서버의 최신 글을 보존했고, 명시적 덮어쓰기 뒤에만 로컬 글이 저장됐다. |
| 하루 일기 충돌 | 실제 PATCH 409 뒤 서버의 최신 글은 유지됐다. 최신 조회 → 보관 초안 복원 → 정상 버전 재저장으로 로컬 글을 저장했다. |
| 실제 UI 개별 기록 삭제 | 사용자에게 합성 기록 한 건의 삭제 확인을 받은 뒤 UI에서 삭제했다. 원본 세션·기록·기억·검색 결과는 제거됐고, 함께 삭제를 선택하지 않은 수동본문 29자는 보존됐다. |

자세한 기기별 동작과 증거는 [동기화·충돌·삭제 기록](verification/mobile-sync-conflict-dc6b20f.json)에 있다. 경합은 실행 중인 모바일 편집기와 정상 서버 RPC로 만들었으며, 두 모바일 VM을 동시에 조작한 시험이 아니다.

각 단계에서 원래 세션·메시지·기록·일기·기억과 프로필 설정의 해시가 동일했다. 정상 계약의 개인정보 처리 revision은 되돌리지 않았다. 차량은 정상 기동 시각인 `last_seen_at`만 제외한 행 해시를 처음부터 고정해 비교했다. 합성 기록은 개인화 제외 상태였고 파생 기억은 0개였다.

## 표시 결함 수정과 정리

`dc6b20f`의 실제 UI 삭제 후 서버에는 29자 수동본문이 남았지만, `status=empty`인 일기를 화면이 숨기는 결함을 발견했다. **서버의 수동본문 손실은 아니었다.** `60141ae`에서 같은 잔존 상태를 Android·iOS 양쪽에 표시하고 편집 본문과 빈 AI 비교 버튼의 부재를 확인했다. 새 빌드에서 삭제 동작 전체를 다시 실행한 시험과는 구분한다. [수정·빌드·회귀 기록](verification/mobile-manual-retention-fix-20261114.json)

양쪽 표시 검증 뒤 남은 고정 시험 일기만 정상 버전 검사와 삭제 계약으로 정리했다. **19:06:27 KST 최종 서버 조회**에서 시험 세션·기록·일기·메시지·기억·작업·일기 이력은 모두 0개였고, 11월 1일·2일의 기록과 일기도 없었다. 기존 실제 기록 3개·일기 1개와 보호 대상 해시는 유지됐으며 Google 계정 1개·활성 연결 차량 1개가 보존됐다.

같은 시각에 대기·실패 작업, 큐 메시지, 미정산 예약은 모두 0개였다. 운영 예산의 보수 차감액은 **$0.103911**이며 44개 예약의 정산 합계와 일치했다. 별도 직접 평가 $0.162422와 설정 확인 유보금 $0.10을 포함하면 알려진 차감·유보 합계는 **$0.366333**이다. 이는 실제 청구서 금액이 아니다. 플랫폼별 최종 온라인 조회·캐시 갱신 결과는 위 기기별 기록에서 구분한다.

고정 시험 자료의 ID·보호용 해시·세부 SQL과 단계별 영수증은 공개 저장소 밖의 비공개 시험 manifest에 보관한다. 실제 기록의 내용은 시험 영수증에도 복사하지 않는다.
